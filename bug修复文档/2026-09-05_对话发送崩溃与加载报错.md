# [2026-09-05] 修复对话发送崩溃与页面加载报错（用户控制台反馈）

- 类型：bug 修复（用户贴出后台控制台报错，据此定位）
- 修复版本：V0.8.3 → V0.8.4
- 状态：✅ 已完成并验证

## 问题现象

用户使用 AI 军师发消息后"一直思考、始终无输出"，并贴出控制台报错：

```
Uncaught TypeError: Cannot read properties of undefined (reading 'id')
    at reload (chat.js:427)  at init (chat.js:467)
Uncaught (in promise) ReferenceError: stickScroll is not defined
    at send (chat.js:286)
```

## 根因（两处，均为 V0.8.2 布局重构时漏改的调用点）

1. **发送即崩溃（直接导致"一直思考无输出"）**：`stick` 滚动模型重构时，
   `stickScroll` 已改名，但 `send()` 里追加思考气泡后的 `stickScroll(true)` 和
   `finishExchange()` 里的一处漏改 → 用户点发送：用户气泡与思考气泡先上屏，
   随后 ReferenceError 中断 send()，**对 AI 的请求根本没有发出** → 思考气泡永远停着
2. **页面加载报错**：chat.js 的 init 早于 app.js 完成账本装载执行，
   `reload()` 里 `getActiveLedger()` 返回 undefined → 读 `.id` 报 TypeError；
   由于报错发生在 init 末尾，聊天的主要功能"碰巧"能用，因此此前未被发现

另：控制台里的 `mcs.zijieapi.com` 被拦、`unload` 违规提示来自浏览器扩展/外部脚本，
与本程序无关；favicon 404 已顺手补上内联 SVG 图标（账字印章）。

## 修复内容

| 修复点 | 说明 |
|---|---|
| send() 崩溃 | 残留的 `stickScroll(true)` → `stick = true; follow(); updateJump();` |
| finishExchange 崩溃 | 同上一处残留一并替换 |
| init 加载崩溃 | `reload()` 增加就绪守卫（app 未装载完直接返回）；init 改为 `waitAppReady()` 轮询到账本就绪后再首次加载 |
| favicon 404 | index.html 加内联 SVG 图标（朱砂账字印章） |

## 验证结果

- ✅ 全新页面加载：chatReady、提示语含账本名（init reload 成功执行）、无报错
- ✅ 发送全链路：用户气泡 + AI 回答气泡（mock 流式）+ 历史入库，全程无报错
- ✅ 上一版已验证的能力（流式打字机/停止/看门狗/画布布局）不受影响

但它只影响 Key 有效后的对话内容；**"点发送一直思考"的直接原因就是本次的发送崩溃**。
