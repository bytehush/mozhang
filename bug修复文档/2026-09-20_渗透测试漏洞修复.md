# [2026-09-20] 渗透测试漏洞修复（存储 XSS / DoS / SSRF / 导入消毒 / CSP）

- 类型：bug修复（安全加固）
- 发现版本：V0.15.5（攻击性渗透测试发现，详见对话记录）
- 修复版本：V0.15.6
- 状态：✅ 已修复并验证

## 问题描述

用户要求以攻击者视角对项目做攻击性测试。静态审计 + 动态实弹验证共发现 2 高危、
4 中危：

| # | 等级 | 漏洞 | 实弹验证 |
|---|------|------|----------|
| 1 | 高 | **存储 XSS**：templates.js 三个模板把备注/项目/日期等字段原样插进 innerHTML（如 `get: r => r.v.note`、`${r.v.item}`），`data-rec-id="${r.id}"` 等属性插值也未转义 | ✅ 浏览器载荷执行，读出 `jigong_settings`（含 API Key 存放位） |
| 2 | 高 | **导入零消毒**：importV2 对外部 JSON 的 `r.id`/`r.v`/customFields `key` 原样入库；导出备份明文含 API Key，备份互传即攻击链 | ✅ 与 #1 组合全链路复现 |
| 3 | 中 | **单请求崩服**：serveStatic 的 `decodeURIComponent` 未捕获异常，`GET /%` 一次打死进程（URIError） | ✅ 实测进程退出 |
| 4 | 中 | **SSRF 绕过**：`URL.hostname` 对 IPv6 保留中括号，`net.isIP("[::1]")` 失效后字符串比对也对不上——`http://[::ffff:127.0.0.1]` 等形态整段漏判 | ✅ 实测回连本机 8787 拿到 405 |
| 5 | 中 | **DEFAULT_SETTINGS 未定义**：导入含设置的备份在账本已合入后抛 ReferenceError（脏状态） | 静态确认 |
| 6 | 中 | **无安全头 + .git 可读**：响应无 CSP/nosniff/XFO；`GET /.git/config` 返回 200 | ✅ 实测 |

另发现：溯源面板 `data-rec="${it.recId}"` 未转义；`locateRecord` 把记录 id 裸拼进
querySelector；smoke.html 自 V0.9.9 起断言脚本带语法错误（字符串内裸换行）从未执行
过——冒烟这道门禁一直是坏的。

## 复现步骤（修复前）

1. XSS：向账本存储写入 `note: "<img src=x onerror=...>"` → 点书架封面渲染 → 载荷执行、
   `window.__STOLEN` 拿到设置 JSON（含各厂商 Key）。
2. DoS：`curl http://127.0.0.1:8787/%` → 进程崩溃退出。
3. SSRF：POST /api/ai 带 `baseUrl: "http://[::ffff:127.0.0.1]:8787/nope"` → 校验放行、
   真实回连本机。

## 原因分析

- 模板函数输出直接进 innerHTML，转义责任没有落在任何一层（模板层没 esc，渲染层也只
  esc 了部分自定义字段）；记录 `id` 虽由 uid() 生成，但导入路径让外部数据绕过了这个前提。
- 防御写成"逐点修补"而不是"出口统一转义"，新增模板/字段就漏。
- IPv6 校验只写了字符串前缀比对，没考虑 URL.hostname 的中括号形态与映射地址。
- smoke 页断言脚本 V0.9.9 改造时引入裸换行语法错误，页面表现为"永远运行中"，无人发现。

## 修复方案

**渲染出口全量转义（纵深防御）**
- `js/templates.js`：三个模板的 columns/card/foot/preview 对一切 `r.v.*`/`r.m.*` 插值包
  `esc()`（money() 数字化输出天然安全，保持不变）；convertLegacyRecord 的 id 一律重建。
- `js/app.js`：renderSummary 的 label/value、data-rec-id/data-tags/data-edit/data-del、
  账本菜单与书架 data-led、renderCfManager 的 data-cf-key/data-cf-del/kind、
  renderModelRows 全部 data-mp*、renderApiTabs data-ap 全部转义。
- `js/chat.js`：溯源面板 data-led/data-rec、会话菜单 data-ss/data-ssdel、模型菜单
  data-ap/data-mid 转义（dataset 读取端拿到的仍是解码原值，事件绑定不受影响）。
- `locateRecord` 选择器：记录 id 先转义引号/反斜杠/换行再拼 querySelector。

**导入消毒（app.js importV2）**
- 记录 `id` 一律 `uid()` 重建（去重靠内容签名，与 id 无关）；
- customFields 的 `key` 必须形如本程序生成的 uid（`/^[\w-]{8,}$/`）否则重建，`kind`
  白名单（text/number/money），`label` 截断 60 字符——外部 JSON 不再有任何原样入库的字符串。

**server.js**
- `decodeURIComponent` 包 try/catch，畸形请求回 400 不再崩进程；
- 路径段以 `.` 开头一律 403（.git/.agents/隐藏文件）；
- 越界前缀比对改为 `ROOT + path.sep`（防同级同前缀目录误放行）；
- 新增安全响应头：CSP（script-src 'self' 等）、X-Content-Type-Options、X-Frame-Options、
  Referrer-Policy。为此把 index.html / smoke.html 的内联脚本外置：
  - `js/errhook.js`（新）：错误收集钩子，两页面共用，必须是第一个脚本；
  - `smoke-tests.js`（新）+ `smoke-stubs.js`（新）：见下。

**SSRF 加固（server.js 与 cloudfunctions/mozhang-ai/index.js 同一套逻辑）**
- hostname 先剥离 IPv6 中括号再 `net.isIP` 判断；
- 新增 `expandIPv6()`：`::` 压缩展开为 8 组 hextet，统一判断未指定/环回/组播/链路本地/
  唯一本地/Teredo；IPv4 映射（::ffff:0:0/96）、NAT64（64:ff9b::/96）、6to4（2002::/16）
  内嵌 IPv4 还原后套同一 v4 黑名单；IPv4 兼容段（::/96）一律拒绝。

**冒烟门禁修复（顺带，已坏 7 天）**
- smoke.html 两段内联脚本外置为 `smoke-tests.js`，修复 V0.9.9 引入的字符串裸换行语法
  错误 + 「会话存取」用例未定义的 `key` 变量；
- 新增 `smoke-stubs.js`：smoke 页没有 index.html 的完整 DOM，初始化需要的 70+ 个元素 id
  在 body 末尾同步补隐藏桩（新增 id 需同步清单，文件头有维护约定）。

**其它**
- `js/app.js` 定义 `const DEFAULT_SETTINGS = {}`（V0.15.4 起被引用但从未定义）。
- index.html 版本徽标 V0.15.5 → V0.15.6。

### 分诊记录

- **能用的方案**（本次实施）：出口统一转义 + 导入白名单消毒 + 服务器容错与安全头 +
  IPv6 归一化校验（本地/云函数同步）。
- **用不上的方案**：undici dispatcher 固定解析 IP 根治 DNS rebinding——Node 未暴露
  undici 模块；且把 https 上游换成 IP 直连会破坏证书校验。
- **暂时不做**（见"边界与后续"）。

## 验证结果

- `node --check`：js/errhook、templates、app、chat、server、云函数 全过。
- `node tests/run-tests.js`：22/22 通过。
- 攻击回归（curl 全套，修复后预期全部被拦）：
  - `GET /%`、`/%zz` → 400，服务存活；`/.git/config`、`/.gitignore`、穿越路径 → 403；
    index.html/js/图标 → 200；安全头四项全部在位。
  - SSRF：`[::ffff:127.0.0.1]`、`[0:0:0:0:0:ffff:127.0.0.1]`、`[::1]`、localhost、
    127.0.0.1、10.0.0.5 → 全部「接口地址被拒绝」。
- XSS 负向验证（真实浏览器）：修复前执行的同一载荷（id + date + note + item 四向量）
  修复后重放 → 零执行、表格内 0 个注入节点、单元格显示转义后的字面文本、`__errors` 为空。
- 浏览器冒烟：主页零报错、39 个图标正常挂载、Chart/GSAP 正常、版本徽标 V0.15.6；
  smoke.html **8/8 全绿**（修复前该页永远停在"运行中…"）。

## 影响范围

- 全部记录渲染路径（表格/卡片/汇总/预览/溯源面板）：正常数据显示不变（esc 只影响
  `<>&"` 四个字符）；历史数据里若真的存过含 `<>` 的备注，现在会显示为字面文本而非被
  当 HTML 解析——这是修复目的本身。
- 导入：外部备份里的记录 id 不再保留（原本也没被功能引用）；不合规的自定义字段 key
  会被重建（正常导出→导入往返不受影响，T5 备份往返测试通过）。
- smoke.html 依赖 smoke-stubs.js 的 id 清单：app/chat 初始化新增元素引用时需同步。
- CSP 生效后页面禁止内联脚本与外域脚本：本项目脚本已全部外置，libs 本地引用不受影响；
  云端部署版若 aiProxy 配 http 地址需靠 connect-src 的 http: 放行（已含）。

## 边界与后续

- **DNS rebinding 残余风险**：校验与 fetch 各自解析一次，攻击者可控 DNS 仍可在两次解析
  之间切换应答（TOCTOU）。本地应用威胁模型下风险可接受，根治需在连接层固定解析结果
  （见分诊"用不上的方案"），记录在案不再追。
- **导出备份仍明文含 API Key**：备份互传场景建议用户知悉。后续可做"导出时可选剔除
  Key/导入时提示含 Key"，属产品决策，未动。
- **云函数 CORS `*`**：收紧需真实部署域名，待云端接入点（V0.15.5 搁置项）恢复时一并配置。
- **modals.js 引用 `window.UTIL.EASE_OUT/EASE_IN` 未定义**（动画回落默认缓动，无功能损
  伤）：渗透测试顺带发现，非安全问题，另行安排。
