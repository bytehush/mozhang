# [2026-09-13] 修复：账本未点开时引用溯源无法定位到记录

- 类型：bug 修复（功能能跑但行为不对）
- 上线版本：V0.13.7
- 状态：✅ 已修复并验证

## 现象（用户报告）

引用溯源功能（AI 回答 → ⛁ 引用数据 → 点击出处跳转）：**账本没有点开时，
无法回溯到那条数据**——点了出处但看不到目标记录。

## 根因

V0.13.0 上线的账本书架改变了「账本」页的结构：该页默认停在**书架**（`#bookshelf`），
记录表被包在 `#ledger-workbench` 里且带 `hidden` 类隐藏，只有点开某本账才显示。

而 `locateRecord`（溯源跳转）只做了：切页签 → 切换账本 → 重置筛选 → 滚动定位，
**没有把工作台打开**。于是：
- `document.querySelector('[data-rec-id=...]')` 能在隐藏的工作台里找到元素（DOM 存在），
  但 scrollIntoView 与高亮闪烁都作用在**不可见的容器**里——用户什么都看不到；
- 从聊天页跳过去时，屏幕上仍是书架，看起来就像"跳转失败"。

## 修复（js/app.js 的 locateRecord）

跳转前强制把工作台打开：

```js
if (shelfTl) shelfTl.progress(1);   // 收掉进行中的书架转场，避免内联样式残留
...
shelfOpen = false;                  // 账本页可能停在书架：确保工作台打开，否则目标记录不可见
switchTab('table');                 // switchTab 内部的 syncShelf 按 shelfOpen 显示工作台
```

配合原有的自动切账本 / 退出多选 / 筛选重置 / 滚动定位 / 高亮闪烁，全链路即可见。

## 验证（浏览器端到端，两个场景）

1. **书架停着 + 跨账本**：当前活动账本为「家用开支」，页面停在书架，
   调用溯源跳转到「服装厂计时工」9月8日的记录 →
   自动切账本、书架隐藏、工作台显示、目标行高亮闪烁 ✓
2. **返回书架后再溯源**：点「◀ 书架」回书架，再溯源到「家用开支」9月9日记录 →
   同样正确打开并高亮 ✓
3. 全程 `window.__errors` 为 0 ✓

## 涉及文件

`js/app.js`（locateRecord 增加 shelfTl 收尾与 shelfOpen=false）。
