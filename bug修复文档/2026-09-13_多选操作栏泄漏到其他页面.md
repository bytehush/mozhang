# [2026-09-13] 修复多选操作栏泄漏到其他页面

- 类型：bug 修复（功能能跑但行为不对）
- 上线版本：V0.11.1
- 状态：✅ 已完成并验证

## 现象

用户在 AI 军师页看到底部悬着记录表的批量操作条（「已选 0 条 / 全选 / 删除 / 完成」），
挡在输入坞下方。

## 根因

`#batch-bar` 是挂在 **body 层**的固定定位操作条（不在任何 panel 内，切页不会自动隐藏），
显示由 `selectMode` 开关。`switchTab()` 切页时**没有退出多选模式**——只要在记录表页开了
多选再切到其他页，批量条就跟着泄漏过来。切账本时有清理逻辑，但切页面这条路径漏了。

## 修复

`js/app.js` 的 `switchTab()`：离开记录表页时自动退出多选——

```js
if (name !== 'table' && selectMode) exitSelect();
```

`exitSelect()` 会清空选中集合、移除 body 的 selecting 类并隐藏批量条；
在非记录表页调用它只是操作隐藏容器的 DOM，无副作用。

## 验证（浏览器复现）

1. 记录表页点「多选」→ 批量条出现 ✓
2. 切到 AI 军师 → 批量条消失、selecting 状态清除 ✓
3. 回记录表页重新开多选 → 切图表页 → 同样自动退出 ✓
4. 顺带按用户窗口尺寸（1256×787）排查横向滚动条：AI 军师页与记录表页
   `scrollWidth ≤ clientWidth`，无溢出（背景光斑 .bg-blob 为固定定位装饰，不引发滚动）✓
5. 全程 `window.__errors` 为 0 ✓
