# [2026-09-20] GUI 破坏性测试：金额溢出/空名账本/模型参数零校验修复

- 类型：bug修复
- 发现版本：V0.15.6
- 修复版本：V0.15.7
- 状态：✅ 已修复并验证

## 问题描述

用户要求以"恶意用户"视角对应用做一轮 GUI 黑盒破坏性测试（浏览器自动化，纯界面操作）。
测试共报 8 个疑点；经代码审查 + 真实浏览器复验，**4 个为真 bug（本次修复），4 个为自动化工具伪影（误报，不改代码）**。

### 真 bug ①：金额溢出零校验，一条脏记录永久污染账本（高危）

- 计件工账本填件数 `1e308`、单价 `1e308`：预览显示 `¥Infinity`，**保存成功**。
- 之后账本汇总变 `¥Infinity / 1e+308 件 / Infinity 件`，图表数据点消失；
  由于 `Infinity + 任何数 = Infinity`，**该账本后续所有正常记录的合计全部作废**。
- 根因：`readForm()` 用 `parseFloat()` 解析（`"1e308"` 合法有限，`"1e400"` 直接 Infinity），
  `validate`/`compute` 链路都没有有限性检查。

### 真 bug ②：新建账本名称必填校验形同虚设 + 切模板清空已填名称（中危）

- 什么都不填直接点"创建账本"：空名账本创建成功（名称静默回退成模板名 `|| tpl.name`），
  界面上名称却标着必填 `*`；AI 建账路径（`createLedgerFromAI`）反而拒绝空名，两条路径不一致。
- 先填名称 → 再点选别的模板：`renderTplPick()` 里 `$('nl-name').value = ''` 把用户已填的名称清空，
  用户不注意就会建出空名账本。

### 真 bug ③：设置页模型参数零校验（中危）

- 模型档案的「上下文(K)」「最大输出」填 `-5`、`999999999`，全部接受并持久化（刷新后仍在）。
- 根因：行内编辑 `f.context = parseFloat(e.target.value) || 128` —— 负数是真值直接通过。
  这种配置会让 AI 请求参数非法，用户只会觉得"AI 坏了"。

### 真 bug ④：负数金额提示文案歧义（轻微）

- 收支账本支出填 `-88` 保存，提示是"收入和支出至少填一项"（因为负数不满足 `> 0` 落进兜底分支）；
  计件工件数/单价、计时工时薪填负数同理——行为上拒绝是对的，但文案让用户困惑。

### 误报 4 个（复验后撤销，未改代码）

| 疑点 | 复验结论 |
|---|---|
| 行内删除无确认 | **误报**：app.js 原有 `confirm('确定删除这条记录吗？…')`（行内与批量删除都有），自动化环境把原生对话框自动"确定"了 |
| 多选底栏在视口外不可用 | **误报**：测试时连点两次「多选」把多选模式切进又切出，量到的是隐藏态（translateY(150%)）位置；`.show` 显示态位置正常 |
| 刷新后首次点导航不切内容 | **误报**：`switchTab` 代码正确、`elementFromPoint` 命中正常、`window.__errors` 为空；是自动化点击事件派发未落地（activeElement 停在 BODY）。已请用户手验 |
| 粘贴超长文本后 Enter 失效 | **误报（待观察）**：keydown 监听只绑一次且 textarea 不会被重建，`send()` 无长度限制；同属自动化输入派发异常 |

## 复现步骤（真 bug ①）

1. 打开计件工账本 → 「记录」
2. 完成件数填 `1e308`，单价填 `1e308`
3. 点保存 → 保存成功，表格与汇总出现 `¥Infinity / 1e+308 件`

## 实现

| 修复 | 文件 | 改法 |
|---|---|---|
| ① 存盘拦截 | `js/app.js` `saveRecord()` | 新增 `hasNonFinite()`：对表单数值 `v` 和算钱结果 `m` 做有限性检查，非有限数 toast 拒存（"数值过大或无效/数值过大：乘算结果超出可记账范围"） |
| ① 导入拦截 | `js/app.js` `importV2()` | 合并外部备份记录时跳过 `v`/`m` 含非有限数的记录（外部数据不可信） |
| ① 显示兜底 | `js/utils.js` `money()` | 非有限数（含 `round2` 的 `n*100` 对 >1e306 输入的二次溢出）一律显示 `¥—`，金额位不再出现 `¥Infinity/¥NaN` |
| ② 名称必填 | `js/app.js` `createLedger()` | 空名 toast「请填写账本名称」并聚焦输入框，删除 `|| tpl.name` 静默回退 |
| ② 保留名称 | `js/app.js` `renderTplPick()` | 切模板只更新 placeholder，不再清空已填名称 |
| ③ 参数夹紧 | `js/app.js` `renderModelRows()` | `clampTokens()`：只接受 ≥1 的有限数（上限 1e7），非法输入回退默认 128/4095 |
| ④ 负数文案 | `js/templates.js` 三个模板 | hourly 加「时薪不能为负数」；piece 加「完成件数不能为负数/单价不能为负数」；general 加「收入和支出不能为负数」——负数单独提示，不再落进"请填写/至少填一项"兜底 |

## 边界与后续

- **误报 4 项未改代码**：其中「删除确认」「首次导航」「超长 Enter」3 项建议用户手动复核一次（自动化点击派发不可信）；如手验确有问题再开新文档。
- **导入功能的非法 JSON / 空文件用例未跑**：自动化环境不支持文件选择器；本次只给导入路径补了非有限数过滤。
- **「清空全部数据」确认机制未验证**：会清掉真实数据，测试中主动跳过。
- 测试遗留数据：书架上的"计时工账本/计件工账本"（空名，测 Bug② 时所建）、XSS 命名收支账本、回归测试账本，可直接删除。
- round2 对 >1e306 的输入乘 100 会溢出——显示端已兜底；若未来要支持天文数字记账，需把 round2 换成不放大再取整的实现（现无此业务需求，不做）。
