# [2026-09-13] 修复：AI 把工具调用写成正文（假调用）——自动降级数据直读

- 类型：bug 修复（行为不对；附带健壮性机制）
- 上线版本：V0.14.9
- 状态：✅ 已修复并验证

## 现象（用户报告 + 截图）

用户提问"基于我的记录，怎样安排能多挣一点？"，AI 回复：

> 当然可以帮你分析一下。首先，我需要查看你的"我·服装厂计时工"账本中的数据…
> 请稍等，我去调取数据。 get_ledger
> {"name":"我·服装厂计时工"}

——**AI 把"调用工具"写成了正文文字**（且 `get_ledger` 是它编的工具名，
本项目的工具是 get_stats/get_daily/…），没有产生任何真实的工具调用与工具卡片。

## 根因分析

模型**没有真正拿到/不会使用工具**（function calling 不可用——模型不支持、
厂商偶发失灵等），但它读到系统提示里"涉及数据必须先调用工具"的规则后，
只能"表演"一个调用动作。这类失败模式与具体厂商/模型相关，**产品侧必须兜住**。

（注：本机测试浏览器的智谱 Key 当前返回 401"令牌已过期"，无法用真实链路复现；
以下修复针对该失败模式本身，与具体 Key 无关。）

## 修复（js/chat.js）

### 1. 假调用检测（流式进行中）

新增特征识别：正文中出现 `{"name":`、裸写工具名 + `(`/换行/`{`、
或 `tool_calls` 字样（典型如 `get_ledger\n{"name":…}`）。仅在**带工具声明的轮次**
里检测，命中即停止展示并丢弃这段"假调用"文本。

### 2. 自动降级「数据直读」模式

命中后：
- 记住该模型（`toolIncapableModels`，本会话内不再重复试探）；
- 清空气泡，改用**数据直读**提示词重答——即 V0.9.x 的"数据快照"方案：
  账本目录 + 当前账本统计 JSON + 每日明细直接装进系统提示，明确告知
  "你无法调用任何工具、禁止在正文写工具名或 JSON"，一条流式给出答案；
- 该轮**不带 tools 参数**，从机制上消除"表演调用"的可能。

### 3. 透明化衔接

- 回答后附诚实徽章：「△ 该模型不支持工具调用，本条已自动改用数据直读」；
- 📦 引用数据/数字核对自动切换依据到快照（复用 V0.9.x 快照对象）；
- 切换瞬间 toast 提示；提示词同时为正常模式加了第 6 条硬规则：
  "严禁在正文中书写工具名或 JSON 参数来假装调用工具"。

## 验证（模拟厂商 SSE 端到端）

| 步骤 | 断言 | 结果 |
|---|---|---|
| 第 1 次请求 | 带 5 个工具声明 | ✓ |
| 模型流式正文写假调用 | 检测命中、假文本不展示 | ✓ |
| 第 2 次请求 | **tools=0** 且系统提示含"数据快照" | ✓ |
| 最终回答 | 降级答案流式显示、0 个假工具卡片 | ✓ |
| 徽章 | 「✓ 数字均有出处」+「△ 该模型不支持工具调用…」 | ✓ |

| 全程 | `window.__errors` 为 0 | ✓ |

## 涉及文件

`js/chat.js`（FAKE_TOOL_RE 检测、buildDegraded 降级提示词、send 降级切换、
finishExchange 诚实徽章、正常模式第 6 条硬规则）。

## 通用教训

**给模型的"规则"必须与它"能力"匹配**——提示词要求"必须先调用工具"，
而模型无工具可用时，它会编造一个调用动作来"遵守规则"。产品侧要有
**能力探测 + 降级链路**：检测到表演行为就切换不需要该能力的工作模式，
而不是让用户看到假动作。
