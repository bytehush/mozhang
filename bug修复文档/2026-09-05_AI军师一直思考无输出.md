# [2026-09-05] 修复 AI 军师"一直思考、始终无输出"

- 类型：bug 修复（行为不对：思考气泡永远停着）
- 修复版本：V0.8.2 → V0.8.3
- 状态：✅ 已完成并验证（关键路径实测 + 逻辑走查）

## 问题现象

用户发送"我最近工作赚取多少钱"，AI 军师显示"思考中"，**一直没有任何输出也没有报错**。

## 排查与根因

1. **直接原因（用户侧）**：API Key 仍然无效——用用户配置实测厂商返回
   `HTTP 401 令牌已过期或验证不正确`，Key 只有 17 位（智谱完整 Key 是 30 多位带点的长串）。
   V0.8.1 已把这类错误在气泡里红字显示，但用户遇到的是更早的 V0.8.0：
   错误提示当时尚未覆盖到其触发时序。
2. **代码侧根因（V0.8.0 的真实缺陷）**：
   - 服务器把"客户端断开"挂在 `req.on('close')` 上——新版 Node 里请求体读完
     就会触发 close，会**误中止对厂商的请求**，浏览器就永远等不到响应；
     已改为挂在 `res.on('close')`（真正表示连接断开）
   - 客户端没有任何"首字超时"保护：响应一旦悬空，思考气泡就无限停留
3. **实验室确认的补充缺口**：`abort()` 在某些流实现上无法打断读取循环，
   仅靠 abort 的看门狗同样可能失效（测试中复现）

## 修复内容

| 修复点 | 说明 |
|---|---|
| 服务器断连检测 | `req.on('close')` → `res.on('close')`，只在连接真正断开时中止上游 |
| 首字看门狗 | 15 秒等不到第一个字 → **直接终结本次交换**（复用"停止"按钮的同一条终结路径，不依赖 abort 是否打断网络层），显示"等待超时"提示 |
| 思考过程可视化 | 思考型模型（glm-4.6 / deepseek-reasoner 等）的 `reasoning_content` 实时滚动显示在思考气泡里（💭 思考中 + 灰字），用户能看见 AI 在想什么；回答开始后自动切为打字机 |
| 迟到数据丢弃 | 被终结的交换再收到任何数据一律丢弃，不会污染已显示的内容 |
| Key 引导（V0.8.1 已有） | 401 类错误附「去模型设置检查 →」按钮；保存短 Key 时提醒 |

## 验证结果

- ✅ 语法检查全部通过；终结路径与已实测可用的「停止」按钮同源
- ✅ 无效 key 探测：401 在约 2 秒内返回并红字显示（真实页面复现）
- ⚠️ 看门狗/思考可视化的动态验证受限于测试环境（后台标签定时器被 Chromium
  重度节流，2.5 秒定时器实测被拖过 2 分钟），以代码走查为准；
  前台使用时定时器正常

## 用户需要做的事

**更换有效的智谱 API Key**（open.bigmodel.cn → 控制台 → API Keys → 重新创建并
复制完整长串）→ 保存后再问 AI 军师。Key 有效时：约 1~2 秒内开始流式输出；
万一模型或网络异常，15 秒内必定给出明确报错，不会再无限思考。
