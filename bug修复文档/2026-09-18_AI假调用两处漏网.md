# [2026-09-18] 修复：AI 假工具调用两处"漏网"——非流式回退丢工具声明、数据直读轮不再检测

- 类型：bug修复（V0.14.9 的检测有两条路径没覆盖到）
- 发现版本：V0.14.9（现象由用户 2026-09-17 截图报告）
- 修复版本：V0.15.4
- 状态：✅ 已修复并验证

## 现象（用户报告 + 截图）

用户提问"基于我的记录，怎样安排能多挣一点？"，军师连续三次都把"表演式调用"当成了回答：

> 当然可以帮你分析一下。首先，我需要查看你的"我·服装厂计时工"账本中的数据…请稍等，我去调取数据。get_ledger
> {"name":"我·服装厂计时工"}

——没有工具卡片、没有真实数据、也没有任何"已降级"的提示。V0.14.9 明明加了"假调用检测 → 数据直读"，
说明这次是从**检测没覆盖的路径**漏过去的。

## 复现（本地模拟厂商，浏览器端到端）

用真实 `js/chat.js` + 拦截 `/api/ai` 模拟厂商行为，两条路径都能稳定复现：

1. **路径①（对应用户截图）**：厂商 SSE 流只回心跳与结束事件、没有正文；
2. **路径②**：厂商 SSE 流里直接吐"假调用"正文。

## 原因分析

V0.14.9 的检测写在"带工具声明的流式轮"的回调里，另有两处绕过：

- **路径①**：流里没收到任何正文时，旧代码改走"非流式重试一次"，但那次请求
  **既没有带 `tools`**（模型根本没有工具可调用），**也没有做假调用检测**。
  模型读到提示词"涉及数据必须先调用工具"，没有工具可用，就"演"了一次调用——
  这段正文被当成最终答案渲染。实测请求日志：`[{stream:true,tools:6},{stream:false,tools:0}]`。
- **路径②**：切到「数据直读」模式后，轮次不再带工具（`withTools=false`），
  检测也被同一个条件一起跳过；弱模型不听"禁止写工具名"的提示再演一次，
  这段假文本同样被当答案显示。

一句话：**"给模型的规则"和"检查模型是否遵守"这两件事，必须覆盖所有路径**——
V0.14.9 只补了主路径，兜底路径成了新的缺口。

## 修复（js/chat.js）

1. **非流式兜底下沉进 `streamRequest`**：流里一个数据都没来（`sawAny=false`）时自动改走
   非流式重试，请求体原样带上（**含 tools**）——从机制上保证模型永远"有工具可用"；
   返回的正文同样过假调用检测。
2. **假调用检测不再按 `withTools` 分流**：任何轮次（含数据直读轮）都检测。
   数据直读轮里再犯 → 直接启用下面的兜底卡。
3. **新增「系统直读兜底卡」`localDataCard()`**：模型既不真调用工具、也不给回答时，
   把当前账本的真实统计 + 每日明细直接摆出来（数字全部来自模板计算，与模型无关），
   并附上"换个支持工具调用的模型"的指引——用户至少拿到真实数据，不会空手而归。
4. **删除旧的裸奔重试**：原"整轮没内容 → 再来一次非流式"的代码（不带 tools、无检测）移除，
   由第 1 条的 transport 层兜底 + 第 3 条的数据卡接管。
5. **诚实徽章**：新增「△ 模型未作答，本条账本数据由系统直接读取」；
   兜底卡同样带 📦 引用数据与数字核对（实测「✓ 59 个数字均有出处」）。
6. 顺带把"数据快照"抽成 `ledgerData()`，数据直读提示词与兜底卡共用同一口径。

## 验证结果（模拟厂商 + 真实 chat.js，浏览器端到端）

| 场景 | 断言 | 结果 |
|---|---|---|
| ① 空流 + 非流式假调用 | 非流式请求 **tools=6**（旧版为 0）；不显示假文本；给出真实数据卡 | ✓ |
| ② 流式假调用（降级后再犯） | 检测在数据直读轮同样生效；假文本全程 0 显示；数据卡 + 双徽章 | ✓ |
| ③ 会真调用工具的模型 | 工具卡片（真实结果可展开）+ 回喂 + 「✓ 数字均有出处」，未受影响 | ✓ |
| 连续发送 3 次 | 3/3 稳定出数据卡，无假文本 | ✓ |
| 全程 | `window.__errors` 为 0 | ✓ |

## 影响范围

- 只改 `js/chat.js`：`streamRequest`（+`allowNonStream`/`sawAny` 与非流式兜底）、
  假调用检测全轮次、`ledgerData()`/`localDataCard()` 抽取、`finishExchange`（+`localFallback` 徽章）。
- 工具调用正常路径、降级数据直读路径、记账草稿卡片均不受影响。
- 用户侧生效方式：**重新打开页面（F5）**即可（静态文件 `Cache-Control: no-store`）。

## 通用教训

**兜底路径最容易成为"没被检查的路径"**——加保护机制时要问一句"还有哪条路能到这个界面"。
本项目的 AI 链路上，能产生"最终回答"的入口有三个（流式轮、非流式兜底、数据直读轮），
保护必须三处齐平，而不是只护住主路。
