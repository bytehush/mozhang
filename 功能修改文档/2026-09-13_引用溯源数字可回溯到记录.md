# [2026-09-13] 引用溯源：每个数字可回溯到账本具体记录

- 类型：功能修改（交互升级，用户提出构想并推演确认）
- 上线版本：V0.12.0
- 状态：✅ 已完成并验证

## 一、构想（用户提出）

数据依据窗口不该铺 JSON 原文（"程序的方言"），而应把 AI 引用的数据做成
**一条条可回溯的出处**——点击能定位到账本里那条具体记录，实现**反向验证**：
AI 说 540 元，你点过去看到三条 180 的记录摆在眼前，信任靠一步之遥的求证建立。

## 二、实现

### 1. 归因引擎（js/chat.js）

- `extractNumRefs(text)`：从回答提取引用的数字（带单位"元/小时/件/天"，跳过日期、
  年份、"1."列表序号，去重，上限 14 条防窗口爆炸）；
- `traceRefs(text, toolCalls)`：从工具参数解析本次交换涉及的账本，为每个账本的每个
  数值字段建"数字池"（一次构建），然后对每个数字四级归因：
  1. **账本原数**——某条记录的某字段恰好等于该数（单位加权：带"元"优先金额字段、
     "小时"优先工时字段），列出全部命中记录（上限 8 条，超出提示"另有 N 条相同数值"）；
  2. **合计/平均·推算**——整字段聚合恰好等于该数（如 540 = 180+180+180），
     展示算式并列出构成记录；
  3. **统计聚合**——数字出现在某工具返回的 JSON 里（如"记录天数": 3）；
  4. **未见账本原数**——都匹配不上，诚实警示"多为推算值，也可能是无依据数字"。

### 2. 跳转定位（js/app.js）

`window.JG.locateRecord(ledgerId, recId)`：目标存在性校验 → 退出多选 →
**自动切换到出处所属账本**（跨账本出处自动切）→ 切记录表 → 若筛选会隐藏目标则重置为
"全部" → 滚动到该记录（scrollIntoView 居中，尊重 prefers-reduced-motion）→
**暗金色高亮闪烁两次**（locate-flash，1.3s×2）。

### 3. 窗口改版

「数据依据」悬浮窗主体从 JSON 原文改为**溯源清单**：每条 = 「引用原文」+ 类型徽标
（账本原数/合计·推算/统计聚合/未见账本原数，四种颜色分级）+ 出处条目列表
（日期 · 字段中文名 · 数值 · 账本名，可点击跳转）；底部折叠保留
「查看原始查询数据（JSON）」供深究。点击出处 → 关窗跳转；
记录已不存在时提示"这条记录已不存在或账本数据有变动"。

## 三、验证（浏览器端到端）

- 归因正确性（基于种子的 3 天×9h×180 元数据）：「540 元」→ 合计·推算
  （正常工资 180+180+180，3 条出处）；「9 小时」「180 元」→ 账本原数；
  「3 天」→ 统计聚合（来自"查询账本统计"）✓
- 点击「540 元」下的出处 → 悬浮窗关闭、切到记录表、目标行获得 locate-flash 高亮 ✓
- 跨账本：直接调用 locateRecord 定位「家用开支」的记录 → 自动切账本并高亮
  "2026-09-09 买菜 ¥50" ✓
- 全程 `window.__errors` 为 0 ✓
- 坑：后台标签页 requestAnimationFrame 不触发导致首次高亮未加上——改为
  setTimeout(60ms) 等待筛选/渲染就绪。
