# [2026-09-13] 书架翻开转场重编排：引入 GSAP timeline 修复割裂感

- 类型：功能修改（动效优化，响应用户反馈）
- 上线版本：V0.13.1
- 状态：✅ 已完成并验证

## 一、用户反馈

1. **翻开动画好奇怪**——建议参照 GSAP 找类似动画；
2. **衔接不连贯**——像剪辑里没做好的转场。

## 二、病因诊断（为什么怪）

1. **翻过了头**：封面 rotateY(-148°)，超过 90° 后观众看到的是封面的**空背面**
   （没有做背面内容），视觉上像"卡片翻走消失了"，而非"翻开书"；
2. **三段硬切**：封面翻开(450ms) / 书架退场(300ms) / 工作台浮现(480ms) 各自独立、
   起止不重叠，切换点生硬——正是"转场没做好"；
3. **运动方向矛盾**：翻开是横向运动，工作台却从底部纵向浮起，方向断裂。

## 三、解法：引入 GSAP（本地 libs，同 Chart.js 模式）

- `libs/gsap.min.js`（3.12.5，72KB，本地文件离线可用，无 npm/CDN 在线依赖）；
- GSAP 的价值不在"动画更多"，而在 **timeline 编排**：多段动画精确重叠、统一缓动、
  单一完成回调——这正是转场（match cut）需要的。

## 四、新转场编排（剪辑语言：全程"向前推近"一个方向）

**翻开**（总时长约 1.0s，段段重叠）：

| 时刻 | 段落 | 运动 |
|---|---|---|
| 0s | 封面掀开 | rotateY 0→**76°**（不过 90°，永远看不到空背面）+ 微放大，power2.in |
| 0.10s | 邻卡先散 | 其余封面淡出缩小 0.94 |
| 0.28s | 镜头推近 | 书架整体 opacity→0 / scale→1.07（向前推进） |
| 0.58s | 交棒 | 书架隐藏、工作台就位（初始 opacity 0 / scale .965 / y 12） |
| 0.60s | 内页浮现 | 工作台推近到位，power3.out——延续"向前"方向 |

**返回书架**：反向——工作台拉远淡出（scale 1.03）→ 书架从推近中归位（scale 1.05→1）。

配套清理：`.bs-inner` 的 transform 过渡移除（避免与 GSAP 逐帧赋值打架，hover 上浮
移交外层 .bs-card）；旧 CSS 转场类（.bs-card.opening / .opening-stage / page-enter）
删除；结束后 `clearProps` 清理内联样式，保证反复翻开无残留；REDUCED / GSAP 缺失
自动回退为直切。

## 七、补记（同日）：翻开方向修正

用户反馈"做成向内翻阅了，应该向外反翻阅"。原 rotationY: 76（正角度）绕左缘
把封面往书架深处倒=向内翻；改为 **rotationY: -76（负角度）**，右缘朝观众方向
掀出来=向外翻开。已用 GSAP 内联值验证（动画中途 rotateY(-18.3°)，负向进行中）。

## 八、补记（同日）：非线性节奏

用户反馈"动画速度可以用非线性动画"。全面更换缓动曲线（原来 power 系偏匀速感）：

- **封面掀开加"预备动作"**（动画十二原则 anticipation）：先向反方向轻压
  rotationY +5°/scale .985（0.11s power1.in），再 **-78° 越掀越快**（0.42s power3.in）；
- 邻卡散开：expo.out（瞬间散开缓缓停）；
- 书架推近：power3.in（加速冲向观众）；
- **工作台落定：back.out(1.2)**（轻微过冲回弹，有"放下一本账"的分量感）；
- 返回：工作台拉远 power2.in，书架归位 back.out(1.1)。

实测（后台测试环境用 setInterval 手动驱动 GSAP 全局时间线绕开 rAF 停摆）：
翻开轨迹 -3°→-78° 证明"先慢后快"，工作台/书架切换与回弹落定均正确，
全程零报错。注：GSAP ticker 走 rAF，后台标签页会冻结、回前台自动补完，
前台使用无感知。
