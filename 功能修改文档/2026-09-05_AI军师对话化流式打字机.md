# [2026-09-05] AI 军师对话化：流式打字机聊天（V0.8）

- 类型：功能修改（AI 军师从"按钮出报告"重构为"对话式聊天"）
- 调整版本：V0.7 → V0.8
- 状态：✅ 已完成并验证

## 调整背景

用户要求把 AI 军师改成**对话形式**：问一句、AI 思考一下、按打字机方式流式输出。
用户特别强调：以前让 AI 直接实现过类似效果但**不好用**，要求先想清方法再动手。

## 方法分析（为什么以前效果不好）

| 常见坑 | 表现 | 本方案对策 |
|---|---|---|
| 一次性返回+假打字机 | 等几十秒毫无反应像死机，然后突然开始念稿 | 真流式：服务器 SSE 透传，模型出字即出字 |
| 打字机直打 Markdown 原文 | `**`/`#` 乱跳或反复重渲染闪烁 | 每帧对"已显示原文"整体过迷你渲染器（先转义），末尾闪烁光标 |
| 固定速度念长文 | 又慢又假 | 自适应缓冲器：网络块进队列，渲染循环按积压量分帧匀速取出 |
| 没有多轮上下文 | 第二句就失忆 | 最近 8 条对话 + 每次注入最新记账统计一起发给模型 |
| 厂商不支持流就没有任何办法 | 直接失败 | 服务器兼容转发 JSON、客户端自动降级为"整段返回+打字机" |

## 具体改动

1. **server.js**：`/api/ai` 新增流式分支——请求带 `stream:true` 时向厂商发起
   SSE 请求并**逐块透传**（不缓冲），浏览器断开时同步 abort 上游；
   厂商返回错误 JSON 时原样转发（不挂死）；SSRF 校验保持不变
2. **js/chat.js（新增，替代 ai.js）**：
   - SSE 读取器：跨 TCP 分块缓冲、逐事件解析 `data:` 行、`[DONE]` 结束
   - 平滑打字机：`makeTyper` 缓冲器（40ms/帧，自适应取出），未完成时挂金色闪烁光标
   - 多轮上下文：system = 模板人设 + 对话风格指令 + 最新统计 JSON；携带最近 8 条历史
   - 历史按账本保存（`jigong_chat_<账本id>`，上限 30 条），切换账本自动换聊天记录
   - 确定性停止：点「停止」立即终结本次交换（保留已出内容并标注"已停止"），
     不依赖网络层中断是否及时
   - 快捷问题 chips：完整分析报告 / 最近趋势 / 健康建议 / 怎么多挣一点
3. **index.html**：AI 面板改为聊天 UI（消息区+快捷 chips+输入行+清空对话）；
   脚本 ai.js → chat.js；版本号 V0.8
4. **css/style.css**：聊天样式（用户墨青金边气泡右侧、AI 墨玉牌气泡左侧带头像、
   思考呼吸点、打字机光标、chips、自适应输入框）
5. **js/app.js**：切换账本与启动时调用 `JGChat.reload()`
6. **js/ai.js 删除**：Markdown 渲染器并入 chat.js；旧"生成分析报告"能力由
   快捷 chip「📋 完整分析报告」承接（对 AI 说一句即得同款报告）

## 验证结果

- ✅ 全链路（mock SSE 模拟"一阵一阵"吐字）：思考气泡 → 首字后流式打字 →
  完成后 Markdown 正确渲染（标题/加粗/列表）→ 历史入库
- ✅ 多轮上下文：第二次请求携带 4 条消息（system + 前两轮）
- ✅ 停止按钮：点击后立即终结，保留"第一段"，迟到的"第二段"被丢弃，
  标注"（已停止，内容不完整）"，发送按钮恢复
- ✅ 真实错误路径（假 key）：厂商 401"令牌已过期或验证不正确"在气泡内红字显示，不挂死
- ✅ 账本隔离：计件账本聊天为空，切回计时工历史还在；清空对话正常
- ✅ 服务器流式错误路径：假 key 流式请求返回厂商 401 JSON（curl 验证）
- ✅ 界面：空状态欢迎语 + 4 个快捷问题 chips + 输入行（Enter 发送/Shift+Enter 换行）

## 影响范围与后续计划

- 数据新增 localStorage 键 `jigong_chat_<账本id>`（聊天历史，按账本隔离），
  清空对话或删除账本不影响记账数据
- 旧报告功能由快捷 chip 承接；`jigong_last_report` 存键不再使用（保留无害）
- AI 回答风格：对话式、简洁（200~500 字）、必须引用数据数字；用户要详细报告时展开
