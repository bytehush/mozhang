# [2026-09-13] 引用数据改悬浮窗：数据依据查看器

- 类型：功能修改（界面与交互优化）
- 上线版本：V0.11.3
- 状态：✅ 已完成并验证

## 一、用户需求

「引用数据」点击后改用**悬浮窗**（不再是消息内联展开）；交互动画遵循既有原则
（POP 从触发处生长/原路归回、200~400ms、尊重 prefers-reduced-motion）；
窗口内容要让用户**直观感受到他在看具体数据、AI 是怎么查到这些数据的**——可靠、可审计。

## 二、设计

**交互**：点击消息悬停图标组里的「⛁ 引用数据」→ 悬浮窗**从该图标生长**（复用
MODAL 系统：POP 380ms EASE_OUT 打开、260ms EASE_IN 原路缩回、ESC/点遮罩关闭、
Tab 焦点圈定、REDUCED 降级直显）——全部符合项目交互六模式的 POP 规范。

**窗口内容 = 一次可审计的"数据依据"报告**，自上而下：

1. **题头**「◆ ⛁ 数据依据」（墨青底金字，与全站悬浮窗同款）；
2. **元信息条**（暗金左线）：账本 · 模型 · 时间——交代"谁、用什么、什么时候查的"；
3. **工具清单逐项摊开**（工具化快照）：每个工具一行
   「🔧 查询账本统计 · 服装厂计时工 ✓」，下方直接铺出该工具返回的**完整 JSON 结果**
   （等宽字体、左线浅底、独立滚动）——AI 查了什么、传了什么参数、拿到了什么，一眼看全；
   旧版非工具快照则整段原文展示；
4. **底部可信说明**：「以上是 AI 回答这条消息时实际拿到的全部数据——界面所见即真实所查，
   回答中的数字都能在这里找到出处。」

数据来源：持久化的 `msg.toolCalls`（每工具 label/参数/结果，历史与实时同一结构），
历史消息打开窗口同样能看到当时查到的数据（结果截断 1600 字的版本）。

## 三、实现

- `index.html`：新增 `#modal-snap` 悬浮窗骨架（body 层，不受聊天区 clip-path 裁剪）；
- `js/chat.js`：新增 `fillSnapViewer(snap, toolCalls)` 填充窗口；
  `buildMsgActions` 增加第 4 参数 toolCalls（appendMsg 传历史 toolCalls、
  finishExchange 传实时 toolLog），引用数据按钮改为 `MODAL.open('modal-snap', 图标)`；
  移除旧的内联 `.cm-snap` 展开逻辑；
- `css/style.css`：新增 .snap-meta / .sv-tool / .sv-raw / .snap-note 窗口内容样式；
  删除废弃的 .cm-snap 样式。

## 四、验证（浏览器实测）

- 点击图标 → 悬浮窗打开（mask 显形、body 锁滚动）、元信息行正确、
  2 个工具块（名称/参数/✓/完整结果 JSON）逐项摊开、底部可信说明在位 ✓
- ESC 关闭 → 窗口隐藏、滚动解锁 ✓（点遮罩/关闭按钮走 MODAL 同一路径）
- 全程 `window.__errors` 为 0 ✓
