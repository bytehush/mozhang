# [2026-09-12] 模型设置改为厂商 API 分组制（V0.9.6）

- 类型：功能修改（模型设置结构重设计，用户指出层级不合理）
- 调整版本：V0.9.5 → V0.9.6
- 状态：✅ 已完成并验证

## 调整背景

用户指出：旧设计"添加一个大模型全部放到一起，乱掉了"。正确的层级应该是
**厂商 → 该厂商的 API（Key/地址）→ 该厂商的多个模型**；切换厂商后，
之前填过的 Key 要自动带出（保存着的），没填过才重新填。

## 新数据结构

```
settings.apis = {                       // 每厂商一套独立 API
  zhipu:   { baseUrl, apiKey, name, models: [{id,label,model,context,maxOut}], currentModelId },
  deepseek:{ ... }, qwen: { ... }, moonshot: { ... }, custom: { ... },
}
settings.activeApi = 'zhipu'            // 当前使用的厂商（切厂商标签即切换）
```

- 每厂商的 Key/地址/模型列表**各自独立保存**：切到智谱填的 Key 不会影响 DeepSeek
- 旧扁平数据（provider/baseUrl/apiKey/models 顶层字段）自动迁移到对应厂商，迁移后清理旧字段

## 具体改动

1. **js/app.js**：
   - `PROVIDERS` → `API_PRESETS`（厂商名/预填地址/预设模型档案，模型档案含 id/名称/模型ID/上下文/最大输出）
   - 设置页改为**厂商标签页编辑器**：五个厂商标签，切到哪个厂商就编辑/使用哪套 API，
     标签切换同时把该厂商设为当前使用（toast 提示）
   - 行内编辑自动持久化（输入即写 localStorage），「保存当前厂商设置」做确认反馈（COMMIT 动效）
   - `window.JG.ModelSwitch` 改为 `activeInfo() / apiList() / selectModel() / ensureApiEntry()`
2. **js/chat.js**：模型快切菜单**按厂商分组**（组头显示厂商名 + 未填 Key 提示），
   点模型 = 切到该厂商 + 选中该模型；发送与摘要使用当前厂商的 Key/地址/模型/最大输出
3. **index.html**：设置卡片改为厂商标签 + 说明文案；移除旧的厂商下拉框与快捷填入 chips
