- 类型：新功能开发（外部方案的本项目化实践）
- 上线版本：V0.14.0
- 状态：✅ 已完成并验证

## 一、缘起与可行性分诊

用户提供了一份《AI 记账系统设计与测试判断标准》（服务器+数据库+多用户的生产级
架构）。该方案**不能照搬**：本项目是本地单机、零依赖、双击即用（localStorage，
无数据库/无多用户/无部署）。按方案自身的"落地建议"（单 agent 起步、主体维度先做
显式、A 类测试先写），把可实践的核心提炼落地：

| 方案要件 | 本项目的实践 | 说明 |
|---|---|---|
| 主体维度（防"用久了分不清"） | ✅ 账本加 `subject{rel,name}` | 建账本必须选"给谁记的" |
| AI 可自主建账本 | ✅ `create_ledger` 工具 | LLM 只决定建什么，创建由 app.js 确定性执行 |
| 隔离四道防线 | ✅ 存储键天然隔离 + 测试证明 | 每账本独立键 + 10 万次模糊测试 |
| 模糊主体必须反问 | ✅ UI 强制选择 + AI 规则 + 工具拒绝 | 三层兜底，绝不猜 |
| A 类测试标准 | ✅ tests/run-tests.js | 22 项断言含 10 万次隔离模糊 |
| PostgreSQL/RLS/多 agent/服务端 Session | ❌ 不搬 | 本地单机无此问题；SQL 与凭据约束不适用 |

## 二、实现

### 1. 主体维度（js/store.js + 界面）

- `SUBJECTS` 预设：我/爸爸/妈妈/爱人/孩子/全家 + 其他（自定义称呼）；
- `normSubject()`：rel 白名单 + 名称必填，非法一律返回 null；
- `migrateSubjects()`：旧账本补 `{rel:'self',name:'我'}`，幂等，启动时自动执行；
- `findDuplicateLedger()`：同主体+同模板+同名 → 判重（对应方案 UNIQUE 约束）；
- 界面：新建账本弹窗加"给谁记的"选择器（chips，默认"我"，"其他"弹自定义输入）；
  书架封面右上角主体签；账本切换器条目显示"主体·名称"；
  备份导出含 subject，导入老备份自动兜底为主体"我"。

### 2. AI 自主建账本（js/aitools.js + js/app.js）

- 新工具 `create_ledger{name, subject_rel, subject_name, template}`：主体/类型
  不明确时确定性拒绝（返回"请先反问用户，禁止默认"），重复账本拒绝；
- `window.JG.createLedgerFromAI`：按模板 defaultsFields 填默认设置；
  **先写记录存储、后写账本列表**——中途失败不会出现"账本在但存储缺"的可见脏状态；
- 账本一律以"主体·账本名"展示；`resolveLedger` 遇同名多本时**报歧义并要求用
  主体区分**（拿不准就反问），裸名唯一才接受；
- chat.js 提示词规则 4/5：建账前必须主体+类型明确、先查重；账本用主体称呼。

## 三、A 类测试（tests/run-tests.js，node 零依赖）

```
▎T1 隔离模糊测试   100000 次随机读写：无跨账本泄漏、无读写不一致（记录+会话键）
▎T2 主体迁移       补默认主体、幂等、不覆盖已有、空输入安全
▎T3 重复账本识别   同主体同名同类判重；换主体/类型/名字不判重；非法主体不判重
▎T4 建账原子性     注入"第二步失败"：账本列表无半成品；成功路径双双就位
▎T5 备份往返       主体字段导出/导入不丢，老备份兜底
```

结果：**22 通过 / 0 失败**（`node tests/run-tests.js` 可随时重跑；FUZZ_N 可调迭代数）。

## 四、验证（浏览器端到端）

- 迁移：现有两本账自动补主体"我"，书架主体签显示正确；

- 同名歧义：两本"工资账本"裸名查询被拒并列出"妈妈·工资账本、张姐·工资账本"，
  全名查询正常；list_ledgers 全部带主体；
- 测试账本已清理，环境复原。

## 五、未采纳与后续（诚实标注）

- 不采纳：PostgreSQL/RLS/连接池、Orchestrator 多 agent、服务端 Session、
  灰度/监控（本地单机无对应基础设施）；
- 仍缺（方案要求但本轮未做）：**AI 写记录**（create_txn 类工具）——需要
  "确认卡片"交互后再做；同名账本的管理建议（归档/改名建议）；
- 观测指标（反问率、同名账本数）在本项目对应人工检查项，暂不做埋点。
