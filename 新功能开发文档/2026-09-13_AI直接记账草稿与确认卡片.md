# [2026-09-13] AI 直接记账：草稿 + 确认卡片（第一期）

- 类型：新功能开发（规划获批后实施；对应外部方案里的 create_txn / A 类最敏感操作）
- 上线版本：V0.15.0
- 状态：✅ 已完成并验证

## 一、需求与安全定位

用户说"帮我记一笔：今天 8 点到 5 点，加班到 7 点"——AI 组装草稿，**程序算钱**，
在聊天里弹出**确认卡片**，用户点「入账」才真正写入。核心原则（规划中确定）：

> **写之前能一眼核对、一键否决；写之后能一键撤销。**

## 二、实现（三层安全设计）

### 第 1 层｜工具层：AI 只能产草稿，不能落盘（js/aitools.js + js/app.js）

- 新工具 `create_record`：**schema 按当前账本模板动态生成**（打平 form 得到字段，
  含 `toggle.block` 嵌套里的加班时段；字段描述带区块上下文如"加班时间段 开始时间"）。
  对话中途换账本/换模板，工具声明自动跟随；
- `window.JG.draftRecord(values)`（工具执行体）：**不写任何数据**——
  字段缺省取账本设置（与手记表单同一 fromLedger 规则）→ 复用模板 `validate()` 校验
  （不合格直接拒绝并回给 AI 去反问）→ 登记草稿队列 → 返回程序 `compute()` 结果；
- 工具参数里没有"账本"这个口子——AI 只能起草到**当前账本**。

### 第 2 层｜确认卡片（js/chat.js + css）

聊天流内联的宣纸签条（账本语言：切角/金线/书法体金额）：

```
拟记账                    记入：我·服装厂计时工
日期 2026-09-01 周二
开始时间 08:00    结束时间 17:00
加班时间段 · 开始时间 17:30    加班时间段 · 结束时间 19:00
─────────────────────────────
正常班：9 小时 × ¥20/时 = ¥180.00
加班：1.5 小时 × ¥30/时 = ¥45.00
当日合计工资：¥225.00（总工时 10.5 小时）   ← 全是程序算的
[ 入账 ]  [ 改一下 ]
```

- 每个数字都来自模板 `compute/preview`，**模型口算的数字一律不显示**；
- 「改一下」→ 光标跳回输入框，让用户直接说怎么改。
- 「入账」后卡片变回执态，附 **[撤销]** 按钮。

### 第 3 层｜落盘层（js/app.js）

- `commitDraft`：入账前**二次校验**（设置可能已变）→ **签名查重**（"这条已经记过了"
  直接拦下）→ 走与手动记账**完全相同**的落盘链路（`dataChanged`：存储+表格+汇总+图表）；
- **幂等**：草稿带状态机（pending/committed/duplicate/expired），同一张卡重复确认无副作用；
- **撤销**：`undoRecord` 删掉刚入账那条，秒级还原；
- **过期作废**：5 分钟 TTL；且**用户发新消息即作废**（防隔很久误点）；
- 切换了账本再点入账 → 拒绝并提示回原账本。

### 规则（提示词）

工具使用规则第 7 条：记账请求信息齐了才起草、信息不够先反问、
**禁止声称"已经记好了"**（入账必须由用户点击触发）；数据直读（降级）模式
提示词同步写清"无法调用记账工具，请引导用户点「记录」按钮"。

## 三、验证

### A 类断言（直接驱动草稿系统，逐条实测）

| 断言 | 结果 |
|---|---|
| 起草后**未确认不落盘**（localStorage 条数不变） | ✓ |
| 卡片行含加班时段（含区块上下文标注）、程序算钱 ¥225（9h×20 + 1.5h×30） | ✓ |
| 非法草稿（缺结束时间）必被拒 | ✓ |
| 入账 → 落盘 +1，存储里加班时段/工资正确 | ✓ |
| **幂等**：同卡再确认，条数不变、仍是同一条记录 | ✓ |
| **查重**：同内容重新起草再入账 → 拒绝"已经记过了" | ✓ |
| **撤销**：条数完全还原 | ✓ |
| 全程 `window.__errors` = 0 | ✓ |

### 端到端（模拟厂商 SSE）

AI 起草 → 卡片出现（截图确认视觉）→ 点「入账」→ toast「已入账 ✓」、
卡片回执 + 撤销按钮、记录正确落盘（加班 17:30~19:00、工资 225）→ 零报错。

### 测试途中发现并修复的 bug

`flattenTemplateFields` 最初只扫 `node.fields`，**漏了 `toggle.block.fields`
里的加班时段字段**（症状：卡片缺两组时间、算钱加班为 0）——已改为递归打平
（fields/rows/block 全支持），并给嵌套字段带上区块名供卡片区分两组"开始/结束时间"。

## 四、涉及文件

`js/aitools.js`（create_record 动态 schema + 递归打平 + run 分发）、

`js/chat.js`（renderDraftCard + 发送时过期 + 提示词第 7 条）、`css/style.css`（.draft-card 皮肤）。

## 五、边界与后续

- **草稿是临时的**：不随聊天历史持久化（刷新即失效——与 5 分钟过期同一设计，够用）；
- **降级模式（模型不支持工具调用）下没有记账能力**：引导用户点页面「记录」手动记；
- 第二期（未做，按规划顺延）：一次多笔批量、AI 改已有记录；
  **永远不做**：AI 删除记录、跨账本写入。
