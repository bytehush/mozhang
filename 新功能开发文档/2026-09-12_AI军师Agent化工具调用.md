# [2026-09-12] AI 军师 Agent 化：工具调用（Function Calling）

- 类型：新功能开发
- 上线版本：V0.10.0
- 状态：✅ 已完成并验证

## 一、需求与判断

用户提出：AI 军师应从"普通聊天机器人"升级为 **Agent（智能体）**——

1. 先感知用户需求，**自主决策**是否需要查询数据（问"你好"不该带着账本数据干活）；
2. 用户判断"把获取数据的程序**封装成工具**去调用"——经确认，这完全正确，即业界标准的
   **Function Calling（工具调用）**模式；
3. 工具调用过程参照 **ZCode** 的方式**内联展示**在 AI 的输出里（查了什么、查到了什么，可展开）。

**改造前的旧机制**：每次提问都把账本统计+每日明细整体塞进提示词——问"你好"也带全量数据，
既浪费 token，AI 也只能看"当前账本"，答不了跨账本问题。

**改造后的新机制**：提示词里只带"账本目录"（名称/类型/记录数，无数字）。AI 遇到数据问题
时**自己决定**调用工具查真实数据，程序本地执行后把结果回喂，AI 再继续决策或作答；
纯寒暄则一次请求直接流式回答。

## 二、四个工具（js/aitools.js 新文件）

| 工具 | 作用 | 数据来源 |
|---|---|---|
| `list_ledgers` | 列出所有账本（名称/类型/记录数/日期范围） | 各账本记录聚合 |
| `get_stats` | 某账本整体统计指标 | 复用模板 buildStats（中文键） |
| `get_daily` | 某账本按天汇总明细（默认 30 天，最大 120） | 按模板字段逐日合计 |
| `get_day_records` | 某天全部原始记录（时段/单价/备注） | 记录原文配中文字段标签 |

关键设计：

- **结果一律中文键**（如"累计工资 540"）：模型引用更稳，界面数字核对也按这些文本比对；
- **跨账本**：`ledger` 参数支持账本名（含模糊匹配），不填默认当前账本——AI 从此可以
  "对比几本账这个月的支出"；
- 找不到账本时报错并**列出可用账本名**，模型下一轮自行纠正。

## 三、Agent 循环（js/chat.js 重写 send/streamRequest）

```
提问 → 第1轮请求（带4个工具声明，stream:true）
  ├─ 模型直接回答 → 流式打字机输出，结束（寒暄路径）
  └─ 模型返回 tool_calls（流式增量碎片按 index 拼装）
        → 每个工具本地执行 → 卡片落成 ✓
        → 结果以 role:"tool" 消息回喂 → 第2轮请求……
        → 最多 3 轮工具调用，第 4 轮不再给工具，强制作答（防无限循环）
```

- 看门狗改为**每轮独立计时**（15 秒无任何数据流动即终止），工具调用的增量碎片也算活动；
- 请求体新增 `tools` 由 server.js 透传给厂商（仅在有工具时携带）；
- 不支持工具调用的模型报错时，提示"换一个支持的模型（如 glm-4-flash、deepseek-chat）"。

## 四、界面：ZCode 式内联工具卡片

- 查询过程在回答上方以**折叠卡片**逐张出现：🔧 中文名 · 参数摘要 → 完成态 ✓/✗；
- **点击卡片展开真实查询结果**（等宽字体、可滚动、截断保护）；
- 查询期间思考气泡文案随状态变化："正在查询账本数据… → 查询完成，继续推演…"；
- 卡片随消息**持久化**：刷新/切会话后仍可展开查看当时查到的数据（结果截断 1600 字防膨胀）。

## 五、透明化与防编造（继承 V0.9.5 理念）

- 📦 引用数据面板 → 展示"本次 AI 通过工具查到的真实数据"；
- 数字核对徽章 → 比对来源从"快照"改为"工具返回结果"；
- **新增诚实提示**：AI 没查数据却在回答里写了 3 个以上数字 → 徽章警告
  "本回答未查询账本数据，数字没有数据来源"；
- 系统提示硬规则同步改写：数字必须来自工具返回结果，没查过的不得编造。

## 六、验证（浏览器端到端，模拟厂商 SSE）

在页面临时接管 fetch 模拟厂商流式返回（真实 Key 仍无效，链路无法真打），验证结论：

- 问「你好」→ 仅 1 次请求、模型不调工具、直接流式回答、无卡片 ✓
- 问「这个月工资多少」→ 第 1 轮返回 2 个工具调用（**名称与参数故意分片传输**，
  拼装正确）、本地执行成功（卡片 ✓✓）、第 2 轮请求含 assistant(tool_calls)+tool×2、
  最终流式回答、数字核对徽章"4 个数字均来自工具查询结果" ✓
- 跨账本：当前在计时工账本，工具查「家用开支」返回正确统计与某日原始记录 ✓；
  模糊匹配「服装厂」→「服装厂计时工」✓；查不存在的账本返回友好错误 ✓
- 历史重渲染：带 toolCalls 的历史消息 reload 后卡片/展开/徽章/面板完整 ✓
- 全程 `window.__errors` 为 0 ✓

（注：后台标签页定时器节流导致打字机收尾在自动化环境里极慢，为环境假象非代码问题，
前台使用正常。）

## 八、遗留与建议

- 工具质量取决于模型：推荐支持 Function Calling 的模型（GLM-4-Flash 免费、deepseek-chat 等）；
- AI Key 仍未验证有效（智谱/DeepSeek 均 401），真实厂商链路待用户换 Key 后首验；
- 后续可选：工具白名单设置、AI 一句话生成账本模板（路线图顺延项）。
