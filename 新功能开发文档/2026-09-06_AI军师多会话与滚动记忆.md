## 需求描述

1. **多会话**：每本账可开多个独立会话（各自历史/状态/存储），支持新建、切换、删除
2. **长对话记忆**：解决此前"记忆系统拉跨、聊长了就失忆"的问题
3. **模型快切**：输入坞内一键切换模型（类似 ZCode 的模型选择器），不必去设置页
4. **用户疑问**：AI 是怎么拿到账本数据的？（本文末尾解答）

## 会话管理设计（针对经典坑逐条防御）

### 数据模型（会话与消息同键，无孤儿数据）

```
jigong_sessions_<账本id>  →  [
  { id, title, createdAt, updatedAt,
    summary: '',            ← 长对话滚动摘要（模型后台压缩）
    summarizedCount: 0,     ← 摘要已覆盖的消息条数
    messages: [{role, content}] } ]
jigong_active_session_<账本id> → 活动会话指针（按账本记忆）
```

| 经典坑 | 防御 |
|---|---|
| 会话串台（消息写错会话） | AI 回答期间**禁止**切换/新建/删除/清空（toast 提示先停止）；消息写入锁定当前会话对象 |
| 活动指针指向已删会话 | 每次装载校验指针，失效自动回落第一个；最后一个会话删掉后自动补空白会话 |
| 旧数据丢失 | 现有单会话聊天（jigong_chat_<id>）自动迁移为首个会话「此前的对话」，原键清除 |
| 会话对象缺失 | currentSession() 永不返回残缺引用；reload 全链路兜底 |

### 界面

- 聊天区顶部左侧：**会话选择器**（📒 + 会话名 + ▾）→ 下拉菜单列出全部会话
  （消息条数 + 更新时间 + 当前高亮 + ✕ 删除），底部「＋ 新建会话」
- 新会话首条消息**自动命名**会话（取前 18 字）

## 长对话记忆设计（滚动摘要，用户此前"记忆系统拉跨"的正解）

发给模型的上下文 = 人设 + 【最新账本统计】+【旧对话滚动摘要】+【最近 8 条原文】：

- 最近 8 条**原文**逐字携带（细节无损）
- 更早的消息由模型**后台自动压缩**成滚动摘要（保留全部数字/结论/未完成事项，300 字内），
  注入系统提示——聊得再长，早期关键信息也不会丢
- 压缩在回答完成后**后台触发**（不阻塞界面），带既有摘要增量更新，失败静默（只影响旧细节）
- 本地消息全量保留（每会话上限 80 条），摘要只是"发给模型时"的压缩视图

## 模型快切

- 输入坞左下角：**当前模型胶囊按钮**（绿点 + "智谱AI · glm-4-flash" + ▾）
- 点开菜单按厂商分组列出全部模型（智谱/DeepSeek/通义/Kimi），选中即存即生效
  （同步写入设置页表单）；自定义厂商仍走设置页

## AI 是怎么拿到账本数据的（用户疑问解答）

AI **从不直接读取**你的原始记录或浏览器存储。流程是：

1. 你提问时，程序先在**本地**用模板的统计函数算出当前账本的关键指标
   （累计工时/工资、日均、最近7天环比、最长连续加班等，见 js/templates.js 的 buildStats）
2. 这份统计 JSON + 最近 90 天每日明细，作为文字**注入提问的上下文**一起发给模型
3. 模型只看到这份"统计摘要文本"，回答时引用里面的数字
4. 原始记录永远只在你的浏览器里；本地服务器仅做转发（带 SSRF 防护），不存储任何数据

## 验证结果

- ✅ 迁移：旧单会话 14 条自动迁入「此前的对话」
- ✅ 新建/切换/删除：自动命名、切换后历史恢复（18 条）、删除活动会话后回落剩余会话
- ✅ 滚动摘要：18 条消息触发后台压缩（覆盖前 10 条），摘要入库；下一次请求的
  system 含【此前对话的要点摘要】，原文窗口恒为最近 8 条
- ✅ 模型快切：四厂商分组菜单、切换即存（provider/model/url 同步）、外点关闭、切回无损
- ✅ 账本隔离：计件账本会话独立；清空本会话同时重置标题与摘要
- ✅ 厂商中文名显示修复（PROVIDERS 补 name 字段）
